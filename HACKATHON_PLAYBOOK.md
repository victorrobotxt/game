# Amusnet Hackathon Playbook

> **Purpose.** This is a field guide for the 36-hour build. It covers what a production PixiJS game looks like inside, the rules we adopt because of it, and code you can paste in.
> **Study target.** [`pixijs/open-games` → *Puzzling Potions*](https://github.com/pixijs/open-games). This is the PixiJS team's own reference game: a timed match-3 written in TypeScript with PixiJS v8, GSAP, @pixi/sound, Spine and AssetPack, built with Vite. It is cloned into `./study-target/`.
> **Starter kit.** Run `bash hackathon-setup.sh my-game` (next to this file). It scaffolds a working slot-style starter with everything below already wired in. `tsc` passes and 11 stress tests pass.
> **Chameleon Engine.** `./chameleon-prototype/` is a full playable game built on the same rules: dual-realm arena, five hot-swappable theme presets, Jackpot Cards draft, phone gyroscope co-op. It uses zero external assets and is verified in a real headless browser. See **Section 9**.

## 0. TL;DR: the eight rules

1. **Logic never imports Pixi.** The model decides; the view only *shows* a decided result.
2. **One FSM owns the game flow.** Input becomes an *event*. Events the current state doesn't list are **ignored, never queued**.
3. **Every async completion is epoch-checked.** A stale `await` must not move the machine.
4. **Every async state and every presentation command has a watchdog.** A hang turns into "fast-forward to the end state", never a frozen screen.
5. **Presentation is a command queue. Skip means jump to the end state, not cancel.** Never `tween.kill()` something you are awaiting; use `totalProgress(1)`.
6. **Lock input synchronously at the start of any transition** (before the first `await`).
7. **Commit money/state before animating.** Animations only *reveal* a state that already exists.
8. **One clock.** GSAP is driven by Pixi's ticker. Cap DPR at 2, use texture atlases and pools, and allocate nothing per frame.

## 2. Findings: how a production PixiJS game is put together

### 2.1 Bundle boundaries and entry point (from REA on `dist/`)

```
index.html
└── assets/index-*.js        699 KB  (210 KB gz)  app + pixi core + gsap + spine + @pixi/ui
    ├── import() WebGLRenderer-*.js    63 KB   ← Pixi v8 picks the renderer at runtime
    ├── import() WebGPURenderer-*.js   37 KB
    ├── import() browserAll-*.js       41 KB   ← event system and accessibility extensions
    └── import() webworkerAll-*.js     55 KB
public/assets/assets-manifest.json  ← generated by AssetPack
    bundles: preload(3) · common(14: atlas, bgm, sfx, spine) · home(1) · game(1) · result(1)
```

- The only code splitting is Pixi's own lazy renderer loading. Game code is one chunk. **For a hackathon this is fine. Don't spend time on manual chunks.**
- Entry `src/main.ts` runs: `app.init()`, then the resize/visibility listeners, then `initAssets()`, then `navigation.setBackground()`, then `showScreen(LoadScreen)`, then `showScreen(HomeScreen)`. URL params (`?game`, `?result`) deep-link straight to a screen. **Copy this for debugging. It saves hours.**

### 2.2 (a) Scene graph and render loop

```
app.stage
└── navigation.container
    ├── background  (TiledBackground; persists across screens)
    ├── currentScreen  (Load | Home | Game | Result; pooled instances)
    └── currentPopup   (Pause | Settings | Info)
```

- **Screen manager** (`study-target/puzzling-potions/src/utils/navigation.ts`). Screens are plain `Container`s that implement an optional lifecycle: `prepare → resize → show() → [update per tick] → hide() → reset`. `show`/`hide` are `async` (GSAP-awaited), so transitions are just `await`.
- **Render loop.** There is no custom loop. `navigation` calls `app.ticker.add(screen.update, screen)` on show and `remove` on hide. Per-piece idle animation uses Pixi v8's `container.onRender` hook. Everything else is GSAP, which runs on **its own** rAF (we fix that in Rule 8).
- **Resize.** There is one `resize(w,h)` fan-out from `window.resize` to every live screen and popup. Layout is code, not anchors.
- **Pooling.** `utils/pool.ts` is a `MultiPool` keyed by constructor. Screens *and* pieces are reused (`setup()`/`reset()` instead of `new`/`destroy`).

### 2.3 (b) Where the logic lives and where the presentation lives

```
screens/GameScreen.ts   ← orchestrator: subscribes to callbacks, drives HUD and VFX
└── match3/Match3.ts    ← facade; owns the subsystems, exposes onMove/onMatch/onPop/onProcessComplete/onTimesUp
    ├── Match3Utility.ts  ← PURE: grid[][] ops (getMatches, applyGravity, fillUp). No Pixi.
    ├── Match3Board.ts    ← grid state + piece sprites (the bridge)
    ├── Match3Actions.ts  ← player intents (move/tap), validated against a CLONED grid
    ├── Match3Process.ts  ← cascade loop as an async queue: stats → specials → pops → gravity → refill → checkpoint
    ├── Match3Stats/Timer/Special.ts
    └── Match3Piece.ts    ← view: sprite + pointer handling + its own tweens + lock()
ui/GameEffects.ts       ← VFX layer reacting to onMatch/onPop (no logic)
```

**The key pattern** is in `Match3Actions.validateMove`: the move is simulated on `match3CloneGrid(...)` with pure functions *before* any sprite moves. The model state (`grid`) changes synchronously, and the sprites then tween to catch up. That is Rule 7.

**Where it falls short:** `Match3Board` and `Match3Process` mix grid mutation and `await piece.animateFall()` in the same method. So you cannot run the logic headless, unit-test it, or replay a server result without the view. **For us: keep the model 100% pure** (see `src/logic/SlotModel.ts` in the starter).

### 2.4 (c) Input guarding and state transitions

There is no explicit FSM. Flow state is spread across booleans, and input is guarded by **interactivity locks**:

| Guard | Where | What it prevents |
|---|---|---|
| `currentScreen.interactiveChildren = false` set **synchronously** before the first `await` | `utils/navigation.ts:129`, `:166` | Double-tapping *Play* starting two screen transitions. Because the lock is set before any `await`, the second tap never reaches a handler. |
| `screen.interactiveChildren = false` during `show()`, restored afterwards | `utils/navigation.ts:90` | Clicking a screen mid-intro |
| Per-piece `lock()` during its tween; handlers early-return on `isLocked()` | `match3/Match3Piece.ts:120`, `:179`, `:253` | Dragging a piece that is mid-swap or mid-fall |
| `if (this.processing) return` re-entrancy guard | `match3/Match3Process.ts:64` | A second cascade loop starting |
| The cascade **re-scans the grid** at each checkpoint instead of trusting the action that triggered it | `match3/Match3Process.ts:198` | Moves made *during* a cascade getting lost |
| Two terminal triggers (`onTimesUp` and `onProcessComplete`) converge on an idempotent `finish()` with a `finished` flag | `screens/GameScreen.ts:243-259` | The timer expiring mid-cascade either soft-locking the game or finishing it twice. **Steal this pattern.** |
| `resolveAndKillTweens()` force-resolves GSAP's internal promise before `killTweensOf` | `utils/animation.ts:27` | **GSAP gotcha:** a killed tween's promise *never* resolves. Anything awaiting it hangs forever, which is a soft-lock. |

### 2.5 Latent race conditions I reproduced at runtime

I ran their `AsyncQueue` (`utils/asyncUtils.ts`) in Node with a scripted scenario:

```
q.add(job1); q.add(job2); …10ms… q.clear(); q.add(new1); q.add(new2)
→ maxConcurrent = 2   (old job1 and new1 ran at the same time)
→ isPaused() returned true while the queue was NOT paused
```

- **`clear()` sets `processing = false` while the old loop is still awaiting** (`asyncUtils.ts:71`). The next `add()` starts a *second* loop, so two cascade loops mutate the same grid. In the shipped game this only happens through `reset()` paths, so it is rare there. In a game with "skip" or "resync" buttons it would be common. **Our queue fixes this with a generation token.**
- **`isPaused()` returns `this.processing`** (`asyncUtils.ts:39`), a copy-paste bug.
- **Keyboard input bypasses every guard.** The game has no keyboard handling, and all locks are `interactiveChildren`, which affects only *pointer* events. If you add a Space-to-spin key on top of this architecture, the locks do nothing. **Guards belong in the FSM, not in the scene graph.**
- `main.ts:56` uses `resolution: Math.max(devicePixelRatio, 2)`. That forces *at least* 2× (4× the pixels on a 1× laptop) and allows 3× on phones. Use `Math.min(dpr, 2)`.

### 2.6 (d) Asset preloading and atlases

- **AssetPack** (`.assetpack.js` + `pixiPipes`). `raw-assets/<bundle>{m}/` folders: `{m}` marks a folder as a manifest bundle. AssetPack outputs texture-packed atlases in **png + webp, at @1x and @0.5x**, plus `assets-manifest.json`. Pixi's resolver picks the format and resolution per device automatically.
- **Loading strategy** (`utils/assets.ts:63-77`):
  1. Fetch the manifest, then `Assets.init({ manifest })`.
  2. `await loadBundles('preload')`. This is tiny: the load screen's own art.
  3. `Assets.backgroundLoadBundle(all)`. Everything else streams in while the player sits on the load and home screens.
  4. Each screen declares `static assetBundles = ['game','common']`. `showScreen()` awaits only what is still missing, so loading is usually instant because the background load has already finished.
- Sprites reference frames by alias (`Sprite.from('highlight')`, `Texture.from(name)`). Use `removeFileExtension: true` so code doesn't depend on file names.

**Our adaptation:** use the same AssetPack config, with three bundles: `preload` (logo and progress bar), `game` (symbols atlas, UI atlas, spine), `audio` (one sprite). Copy `.assetpack.js` from `study-target/puzzling-potions/` verbatim if you add art: `npm i -D @assetpack/core` and `npx assetpack`.

## 3. The "Amusnet Standard" architecture

```
            ┌───────────────── input funnel ─────────────────┐
 pointer ───┤  primaryAction(): switch (fsm.state)            │
 keyboard ──┤   IDLE → fsm.send('SPIN')                       │
 (no e.repeat)  SPINNING → slam()   (intent flag)             │
            │   PRESENTING → queue.fastForward()              │
            └──────────────┬──────────────────────────────────┘
                           ▼
 ┌──────────── FSM (flow, guards, watchdogs) ────────────┐
 │ IDLE ──SPIN──▶ SPINNING ──RESULT──▶ PRESENTING ──DONE──▶ IDLE
 │                   │ TIMEOUT              │ TIMEOUT ─────▶ IDLE
 │                   ▼                                     │
 │                 ERROR ──RECOVER──▶ IDLE                 │
 └───────┬────────────────────────────────┬───────────────┘
         │ enter(ctx): await model.spin() │ enter(ctx): queue.add(...).run()
         ▼                                ▼
 ┌─ Model (pure TS) ─┐          ┌─ CommandQueue (presentation) ─┐
 │ balance, RNG/RGS  │ result → │ stop-reel-0..n, win-lines,    │
 │ no Pixi/GSAP/DOM  │          │ count-up, commit-balance      │
 └───────────────────┘          └──────────────┬────────────────┘
                                               ▼
                                  Views (Pixi Containers, return gsap Animations)
                                  app.ticker ──drives──▶ gsap.updateRoot + render
```

## 4. Bulletproof FSM

### Guarantees (each covered by `test/stress.ts`)

| # | Guarantee | Defends against |
|---|---|---|
| 1 | Events not in the current state's `on` table are **ignored** and return `false`. Nothing is buffered. | Key/click spam: in the test, 1000 sends in a single tick produced exactly 1 transition |
| 2 | `ctx.send()` is bound to the **epoch** of the state that created it | A late server response or tween from a state you already left moving the machine |
| 3 | `ctx.signal` aborts on exit | Wasted work and double side effects (pass it to `fetch` and check it after each `await`) |
| 4 | Per-state watchdog (`timeoutMs` + `timeoutEvent`) | A hung network request or animation |
| 5 | A `throw` or rejection in `enter` sends the machine to `errorState` | Uncaught exceptions freezing the flow |
| 6 | `send()` during `exit()` or a listener is dropped | Half-applied, interleaved transitions |
| 7 | `can(event)` is the only source of truth for UI enablement | View and logic disagreeing about which buttons work |

### Usage rules

- **Flow events vs. intents.** A press that should *change state* is an FSM event. A press that should *modify the current state* (STOP while spinning, SKIP while presenting) is a direct call, gated by `switch (fsm.state)` in a single input funnel. Never queue raw inputs.
- `keydown`: always do `if (e.repeat) return;`. Holding Space must not auto-spin.
- Don't put the FSM in the scene graph. `interactiveChildren` is a nice extra for pointers only (see 2.5).
- Watchdog timers run on wall-clock time, so a backgrounded tab can trip them. That is safe by construction, because every timeout path *fast-forwards to a correct end state*. Make sure your `TIMEOUT` targets uphold this.

### `src/core/FSM.ts`

```ts
/**
 * Table-driven finite state machine that cannot be soft-locked by input spam.
 *
 * Guarantees:
 *  1. Events not listed in the current state's `on` table are IGNORED (never queued).
 *  2. Async work started in a state can only move the machine while that state is still
 *     current: ctx.send() is bound to an epoch, stale completions are dropped.
 *  3. Leaving a state aborts ctx.signal, so its in-flight work can bail out early.
 *  4. Every state may declare a watchdog (timeoutMs + timeoutEvent).
 *  5. A throw/reject in enter() routes to `errorState` instead of freezing.
 *  6. send() from exit() or a listener is dropped (no half-finished transitions).
 */
export interface StateContext<E extends string> {
    readonly signal: AbortSignal;
    send(event: E): void;
}

export interface StateDef<S extends string, E extends string> {
    on: Partial<Record<E, S>>;
    enter?(ctx: StateContext<E>): void | Promise<void>;
    exit?(): void;
    timeoutMs?: number;
    timeoutEvent?: E;
}

export type Listener<S extends string, E extends string> = (to: S, from: S, event: E | 'FORCE') => void;

export class FSM<S extends string, E extends string> {
    private readonly states: Record<S, StateDef<S, E>>;
    private readonly errorState: S;
    private readonly listeners = new Set<Listener<S, E>>();
    private current: S;
    private epoch = 0;
    private abort = new AbortController();
    private watchdog?: ReturnType<typeof setTimeout>;
    private transitioning = false;

    constructor(states: Record<S, StateDef<S, E>>, initial: S, errorState: S) {
        this.states = states;
        this.errorState = errorState;
        this.current = initial;
        this.enter(initial);
    }

    get state(): S {
        return this.current;
    }

    /** Use this to enable/disable UI (buttons, cursor) - never duplicate the table in views. */
    can(event: E): boolean {
        return !this.transitioning && this.states[this.current].on[event] !== undefined;
    }

    /** Returns true if the event caused a transition. Safe to call any number of times. */
    send(event: E): boolean {
        if (this.transitioning) return false;
        const to = this.states[this.current].on[event];
        if (to === undefined) return false;
        this.transition(to, event);
        return true;
    }

    /** Escape hatch for errors / server resync. Bypasses the table. */
    force(to: S): void {
        if (this.transitioning) return;
        this.transition(to, 'FORCE');
    }

    onChange(listener: Listener<S, E>): () => void {
        this.listeners.add(listener);
        return () => this.listeners.delete(listener);
    }

    private transition(to: S, event: E | 'FORCE') {
        const from = this.current;
        this.transitioning = true;
        try {
            clearTimeout(this.watchdog);
            this.abort.abort();
            this.states[from].exit?.();
        } catch (err) {
            console.error(`[FSM] exit(${from}) threw`, err);
        }
        this.current = to;
        try {
            this.listeners.forEach((l) => l(to, from, event));
        } catch (err) {
            console.error('[FSM] listener threw', err);
        }
        this.transitioning = false;
        this.enter(to);
    }

    private enter(state: S) {
        const epoch = ++this.epoch;
        this.abort = new AbortController();
        const def = this.states[state];
        const ctx: StateContext<E> = {
            signal: this.abort.signal,
            send: (e) => {
                if (epoch === this.epoch) this.send(e);
            },
        };
        if (def.timeoutMs !== undefined && def.timeoutEvent !== undefined) {
            const ev = def.timeoutEvent;
            this.watchdog = setTimeout(() => {
                console.warn(`[FSM] watchdog fired in ${state}`);
                ctx.send(ev);
            }, def.timeoutMs);
        }
        try {
            const result = def.enter?.(ctx);
            if (result instanceof Promise) result.catch((err) => this.fail(epoch, state, err));
        } catch (err) {
            this.fail(epoch, state, err);
        }
    }

    private fail(epoch: number, state: S, err: unknown) {
        if (epoch !== this.epoch) return; // state already left; nothing to recover
        console.error(`[FSM] enter(${state}) failed`, err);
        if (state !== this.errorState) this.force(this.errorState);
    }
}
```

## 5. Async presentation command queue with `skip()` / fast-forward

### Semantics

| Call | Effect |
|---|---|
| `queue.add(name, cmd, { skippable?, timeoutMs? })` | Appends a command. `cmd(ctx)` awaits **only** through `ctx.play(anim)` / `ctx.wait(s)`. |
| `queue.run()` | Drains the queue. Calling it again while draining returns the **same** promise, so a double run is impossible. |
| `queue.skip()` | The current command's tweens jump to their final frame and its `await`s resolve at once. The next command plays normally. |
| `queue.fastForward()` | The current command *and every remaining one* run in "skipped" mode: all logic executes, all tweens land instantly. Calling it before `run()` pre-arms it (slam-stop). |
| `queue.clear()` | Hard reset (screen change or server resync). The **generation token** guarantees the old drain loop can't touch new state. This is the fix for the bug in 2.5. |
| `queue.speed = 2` | Turbo mode: multiplies the timeScale of every animation played through the queue. |
| `ctx.signal` | Fires on skip. Hook Howler (`playSfx(name, ctx.signal)`), particles and anything else that isn't GSAP. |

### The three laws of skippable commands

1. **Skip = run to the end, never "don't run".** A skipped command still executes; it just has zero duration. Logic inside it (balance commit, flags) always runs.
2. **Set the final state unconditionally after the await**, for example `winText.text = "WIN " + r.win`. Don't rely on the last `onUpdate`.
3. **Never `kill()` an awaited tween.** GSAP never resolves a killed tween's promise (the study target hit exactly this; see `resolveAndKillTweens`). `ctx.skip()` uses `totalProgress(1)`, which fires `onUpdate`/`onComplete` at the end values. Avoid `repeat: -1` inside commands: an infinite tween has no end state. Put idle loops in the view instead.

**Safety nets:** each command has a watchdog (default 10 s). Hung or throwing commands are logged, force-skipped, and the queue continues. The test suite covers this.

### `src/core/CommandQueue.ts`

```ts
import gsap from 'gsap';

/**
 * Handed to every presentation command. Commands MUST await animations through
 * ctx.play()/ctx.wait() so that skip() can fast-forward them.
 *
 * Rule: skipping means "jump to the final visual state", never "don't run".
 * A skipped command still executes; its tweens just complete instantly.
 */
export class CommandContext {
    private readonly abort = new AbortController();
    private readonly anims = new Set<gsap.core.Animation>();
    readonly speed: number;

    constructor(speed: number) {
        this.speed = speed;
    }

    get skipped(): boolean {
        return this.abort.signal.aborted;
    }

    /** Hook non-GSAP cleanup (Howler sounds, particles) to skip. */
    get signal(): AbortSignal {
        return this.abort.signal;
    }

    /** Await a tween/timeline. On skip it is jumped to its end - never kill()ed, which would hang the promise. */
    play(anim: gsap.core.Animation): Promise<void> {
        anim.timeScale(anim.timeScale() * this.speed);
        if (this.skipped) {
            anim.totalProgress(1);
            return Promise.resolve();
        }
        this.anims.add(anim);
        return new Promise<void>((resolve) => {
            const done = () => {
                this.anims.delete(anim);
                this.abort.signal.removeEventListener('abort', done);
                resolve();
            };
            this.abort.signal.addEventListener('abort', done);
            anim.then(done); // .then() keeps the tween's own onComplete intact
        });
    }

    /** Skippable delay that respects gsap.globalTimeline pause (e.g. pause popup). */
    wait(seconds: number): Promise<void> {
        return this.play(gsap.delayedCall(seconds, () => {}));
    }

    skip(): void {
        if (this.skipped) return;
        const running = [...this.anims];
        this.abort.abort();
        for (const anim of running) anim.totalProgress(1);
    }
}

export type Command = (ctx: CommandContext) => void | Promise<void>;

export interface CommandOptions {
    /** Non-skippable commands ignore skip()/fastForward() (e.g. a mandatory big-win minimum). */
    skippable?: boolean;
    /** Watchdog: a command that hangs longer than this is force-skipped and the queue moves on. */
    timeoutMs?: number;
}

interface Entry {
    name: string;
    run: Command;
    skippable: boolean;
    timeoutMs: number;
}

export class CommandQueue {
    private readonly entries: Entry[] = [];
    private current: Entry | null = null;
    private ctx: CommandContext | null = null;
    private draining: Promise<void> | null = null;
    private fastForwarding = false;
    private generation = 0;
    /** Turbo mode: multiplies the timeScale of everything played via ctx.play(). */
    speed = 1;

    add(name: string, run: Command, opts: CommandOptions = {}): this {
        this.entries.push({ name, run, skippable: opts.skippable ?? true, timeoutMs: opts.timeoutMs ?? 10_000 });
        return this;
    }

    /** Drain the queue. Calling it again while draining returns the same promise. */
    run(): Promise<void> {
        return (this.draining ??= this.drain());
    }

    get busy(): boolean {
        return this.draining !== null;
    }

    /** Fast-forward the current command only. */
    skip(): void {
        if (this.current?.skippable) this.ctx?.skip();
    }

    /** Fast-forward the current command and every queued one to their end states. */
    fastForward(): void {
        this.fastForwarding = true;
        this.skip();
    }

    /** Hard reset (screen change, server resync). An in-flight drain() exits without touching new state. */
    clear(): void {
        this.generation++;
        this.entries.length = 0;
        this.ctx?.skip();
        this.ctx = null;
        this.current = null;
        this.draining = null;
        this.fastForwarding = false;
    }

    private async drain(): Promise<void> {
        const generation = this.generation;
        try {
            while (this.entries.length && generation === this.generation) {
                const entry = this.entries.shift()!;
                const ctx = new CommandContext(this.speed);
                this.current = entry;
                this.ctx = ctx;
                if (this.fastForwarding && entry.skippable) ctx.skip();
                await this.execute(entry, ctx);
            }
        } finally {
            if (generation === this.generation) {
                this.current = null;
                this.ctx = null;
                this.draining = null;
                this.fastForwarding = false;
            }
        }
    }

    private async execute(entry: Entry, ctx: CommandContext): Promise<void> {
        let timer: ReturnType<typeof setTimeout> | undefined;
        const watchdog = new Promise<void>((resolve) => {
            timer = setTimeout(() => {
                console.warn(`[CommandQueue] "${entry.name}" timed out - forcing`);
                ctx.skip();
                resolve();
            }, entry.timeoutMs);
        });
        try {
            await Promise.race([Promise.resolve().then(() => entry.run(ctx)), watchdog]);
        } catch (err) {
            console.error(`[CommandQueue] "${entry.name}" threw`, err);
            ctx.skip();
        } finally {
            clearTimeout(timer);
        }
    }
}
```

### Example: slot presentation with slam-stop (from `src/main.ts`)

```ts
PRESENTING: {
    on: { DONE: 'IDLE', TIMEOUT: 'IDLE' },
    timeoutMs: 15000,
    timeoutEvent: 'TIMEOUT',
    async enter(ctx) {
        const r = result!;
        for (let reel = 0; reel < REELS; reel++) {
            queue.add(`stop-reel-${reel}`, async (c) => {
                await c.play(reels.stopReel(reel, r.grid[reel])); // view applies final symbols sync, tween is juice
                await c.wait(0.12);
            });
        }
        if (r.win > 0) {
            queue.add('show-win-lines', (c) => c.play(reels.showWin(r.winningRows)));
            queue.add('count-up', async (c) => {
                const counter = { v: 0 };
                await c.play(gsap.to(counter, { v: r.win, duration: 1.2,
                    onUpdate: () => (winText.text = `WIN ${Math.round(counter.v)}`) }));
                winText.text = `WIN ${r.win}`; // law #2
            });
        }
        queue.add('commit-balance', () => showBalance());
        if (slamRequested) queue.fastForward(); // STOP was pressed while spinning
        await queue.run();
        ctx.send('DONE');
    },
    exit() { queue.clear(); showBalance(); },
},
```

For non-skippable beats (regulatory minimum win display, a feature intro), use `queue.add('bigwin', cmd, { skippable: false })`.

## 6. Locked 60 FPS checklist

| Do | Why |
|---|---|
| `gsap.ticker.remove(gsap.updateRoot); app.ticker.add(t => gsap.updateRoot(t.lastTime / 1000));` | One rAF. Tweens and render land on the same frame (no jitter), and pausing `app.ticker` pauses everything. |
| `resolution: Math.min(devicePixelRatio, 2)`, `autoDensity: true` | A 3× DPR phone has 2.25× the pixels of 2× with no visible gain. Fill rate is the #1 mobile bottleneck. |
| All art in **AssetPack atlases** (one per screen) | Batching: sprites that share a base texture draw in one call. Check draw calls with the PixiJS DevTools extension. |
| **`BitmapText`** for anything that changes often (counters, timers) | `Text` re-rasterises a canvas texture on every change. |
| **Pool** sprites and particles (`setup()`/`reset()`, like `utils/pool.ts`) | No GC hitches during cascades. |
| Allocate nothing in `ticker` callbacks: no closures, arrays or `{x,y}` per frame | Same reason. `ReelsView.update` throttles via an accumulator. |
| Static complex groups: `container.cacheAsTexture()` (v8) | Collapses many draw calls into one. Call `updateCacheTexture()` when the group changes. |
| `Graphics`: build once, then move/tint/scale it. Never `clear()` and redraw per frame. | Re-tessellation is expensive. |
| Filters (blur, glow) only on small, short-lived objects; prefer pre-baked glow sprites | Each filter costs an extra render pass. |
| Spine: cap simultaneous skeletons; pre-load in `preload`/`game` bundles | Mesh skinning is CPU-heavy. |
| `visibilitychange` → `Howler.mute(hidden)` plus pause or fast-forward | Browsers throttle rAF in background tabs. Without this you get desync and sound on return. |
| Time-based motion: use `ticker.deltaMS`, never frame counts | 120 Hz displays and dropped frames. |

## 9. Chameleon Engine: *The Alchemist's Parallel Clock* (`./chameleon-prototype`)

A top-down arena puzzle-survival game that can pivot to most Edition 02 themes in about ten minutes. It uses **100% procedural assets**: every texture is baked from `Graphics`/`Text` into `RenderTexture`s at boot, and every sound is a WebAudio oscillator or noise burst. It follows Rules 1–8 above: pure engine, one FSM per flow, a skippable `SequenceRunner`, and one clock.

```bash
cd chameleon-prototype
npm install
npm run dev            # http://localhost:5173  (phone: http://<LAN-IP>:5173/controller.html)
npm run dev:https      # same, self-signed TLS, needed for phone tilt (see 9.4)
npm test               # 24 vitest tests (engine rules, difficulty, coin vacuum, attract bot, FSM/SequenceRunner stress)
npm run e2e            # live browser playtest, 74 checks, writes ./screenshots/
npm run check          # tsc + vitest + e2e: run this before every demo
```

### 9.1 Controls

The game boots into a **title screen** (two clocks, Sofia + Malta, on one beat). After 15 s idle it plays itself (**attract mode**).

| Input | TITLE | PLAYING | Jackpot Cards draft | Results card |
|---|---|---|---|---|
| `WASD` / arrows / phone joystick / touch hold-and-drag | n/a | move | n/a | n/a |
| `SPACE` / tap / phone big button | start | shift realm (on-beat = PERFECT combo + bigger shockwave). In SHADOW_LENS: lens flare | DEALING: fast-forward · PICKING: **slam-stop** · REVEALING/AWARDING: **skip** | rewind (new run) |
| mouse / phone tilt | n/a | aim (SHADOW_LENS cone) | click cards to flip (face-down cards lift on hover) | n/a |
| `1`–`5` or HUD buttons | pick preset | hot-swap theme preset (skin, music, rules) | n/a | n/a |
| `T` | **60-second guided tour** | same | n/a | n/a |
| `J` | n/a | open draft (pitch-demo trigger) | n/a | n/a |
| `M` / `C` | mute / **calm mode** (less flash + shake, no hit-stop); both shown as HUD chips | same | same | same |
| `ESC` / `R` | n/a | back to title | n/a | title / rewind |

During attract mode or the tour, **any key, click or phone press** hands control back. URL flags: `?seed=42` reproducible run (the HUD shows the seed), `?play` skip the title, `?calm=1` calm mode (on by default under `prefers-reduced-motion`), `?tutorial=0` no first-wave coach.

### 9.2 Architecture

```
src/
  core/FSM.ts, CommandQueue.ts     ← unchanged from the starter (Sections 4–5)
  core/SequenceRunner.ts           ← alias: SequenceRunner = CommandQueue
  engine/                          ← PURE: no pixi.js, gsap or DOM. Fixed 60 Hz step, seeded RNG, pooled arrays
    World.ts                       ← realms, walls, runes, enemies, chain-reaction blasts, coins (expire after 9 s; a 3+ chain vacuums them), 5 theme rule-sets
    BeatClock.ts                   ← the one clock: position in beats, per-preset BPM (100/124/92/108/84), PERFECT window
    Bot.ts                         ← attract-mode autopilot: lures the pack over the other realm's runes, shifts on the beat
    types.ts                       ← Realm / Theme / Suit / PowerUpKind as `as const` objects + GameEvent union
    Upgrades.ts                    ← suit tiers → PlayerStats (speed, cooldown, magnet, HP, shield, blast, crit)
    easter-eggs/JackpotCardsDraft.ts   ← 12-card model + DEALING→PICKING→REVEALING→AWARDING→DONE table
    easter-eggs/PortfolioCameos.ts     ← MINI/MINOR/MAJOR/GRAND link, Crown / Cash Bomb / Frog rules
  view/                            ← Pixi v8. Reads the World, never writes it
    Palette.ts                     ← SKINS: a Solar + Shadow palette per preset, TITLE_STYLES: font/frame per preset
    ArenaMotifs.ts                 ← floor art per preset × realm (sundial, reactor hex, transmutation circle, gears, noir rain), baked once
    TextureFactory.ts              ← every sprite baked at boot (player, enemies, round solar rune, diamond shadow rune, coin, crown, 7, frog, cards…)
    ArenaView.ts                   ← index-aligned sprite pools, skin crossfade, circle realm wipe, beat ring + cooldown arc on the player, rune "about to cross" warning
    HudView.ts                     ← responsive HUD (wide / medium / compact < 900 px), coin link, one clock, title screen, results card, coach, demo captions
    DraftView.ts / DraftPresenter.ts   ← card flips return gsap timelines → awaited via SequenceRunner
  juice/JuiceManager.ts            ← trauma² shake, 45 ms hit-stop, ObjectPool: 250 particles + 40 labels
  juice/ProceduralAudio.ts         ← coin scale climb, sub-bass shift drop, noise explosions, card snap, fanfare, music bus + filter sweep
  juice/ProceduralMusic.ts         ← look-ahead sequencer on the BeatClock: kick/hat/bass/arp, major (Solar) vs relative minor (Shadow), one style per preset
  net/GyroClient.ts, controller.ts, protocol.ts
  main.ts                          ← app init, flow FSM (TITLE/PLAYING/DRAFT/GAME_OVER/ERROR), attract + tour script, coach, phone mirror, input funnel, event→juice, debug hook
vite-plugin-gyro-relay.ts          ← WebSocket relay on /ws-gyro (both directions; caches the last game packet for late phones) + GET /gyro-info
controller.html                    ← phone page (joystick, tilt, big button), 30 Hz packets; mirrors realm colours, button label, tempo; vibrates on hits
e2e/playtest.mjs                   ← Playwright playtest
```

**Data flow:** input → `InputFrame` → `world.step()` (pure) → `world.events[]` → `main.ts handle()` → particles, shake, audio, HUD. The engine never awaits anything. Async work only exists in presentation (draft and popups), so the starter's epoch and watchdog guarantees cover all of it.

**Core loop (the hook):** enemies chase you in *both* realms but only avoid runes of *their own* realm. Lure a solar enemy across a shadow rune and it **transmutes**. Every death is a blast that damages enemies of *either* realm, which is what makes chains cascade. Shifting on the beat (the preset's BPM, ±130 ms) builds a combo and a stronger shockwave. The rhythm is shown on the player: a ring closes onto the alchemist and flashes inside the PERFECT window, an arc shows the cooldown, and pips show the combo.

**Difficulty (arcade tension from wave 1):** 3 starting flasks (HEARTS tiers grow it to 6); shield regen halved and paused for 4 s after a hit; enemies 40 % faster with 45 % faster spawns and a 5-foe opening burst from all edges; an enemy of the realm you are IN that gets within 160 px shudders for 0.25 s (red warning arrow) then lunges at 1.6× (shifting away cancels the windup); a shift outside the GOOD window (±220 ms) still shifts but shows MISTIMED! and locks shifting for 1.25 s (red cooldown arc). Constants live at the top of `World.ts`.

**Jackpot Cards cadence:** the draft opens only when the coin link hits GRAND (20 coins) or after every 3rd cleared wave (`DRAFT_EVERY`); other waves roll on after a 2 s break (`WAVE_BREAK`). `J` stays a manual debug key.

**Phones:** portrait screens (`w/h < 0.85`) rotate the arena 90° and scale it to the screen width (12 px margins); a camera follows the alchemist along the long axis, the arena is masked to the space between the HUD bars, and arrows at the viewport edge mark enemies above/below the view; all movement input (keys, joystick, phone pad, tilt) is converted screen→arena so up is always up, and floating labels stay upright. Touch is tracked by `pointerId`: thumb 1 is a joystick anchored where it landed (86 px base, 20 px nub clamped to 45 px, hidden whenever the flow is not PLAYING), any second finger is SPACE on pointerdown without disturbing thumb 1, a quick lone tap is SPACE, and tapping outside the draft cards slam-stops/skips. Short touch landscape (`innerHeight < 520`) shows a ROTATE PHONE TO PORTRAIT overlay and pauses everything. `index.html` disables selection, the iOS callout, drag, tap highlight, touch-action and overscroll; `contextmenu`/`selectstart`/`dragstart`/`gesturestart` and canvas `touchstart`/`touchmove` are prevented.

**Teaching it:** in waves 1–2 a coach line walks through (1) shift on the beat, (2) lure foes over the *other* realm's runes, (3) chain PERFECT shifts. Any rune that a foe of the other realm is about to cross flashes and grows a tightening warning ring.

### 9.3 The five presets (`Keys 1–5`)

Pressing 1→5 visibly and audibly reskins the game: palette (both realms), floor motif, banner typography and frame, tempo and music style all change, not only the rules.

| # | Preset | Look / sound | Rule delta (in `World.ts`) | HUD widget |
|---|---|---|---|---|
| 1 | PARALLEL_SYNC | gold sundial grid vs violet star lattice · serif · 100 BPM square-wave arp | base rules + two pressure switches (both held = SYNC burst) | switches, best combo |
| 2 | CHAIN_OVERLOAD | cold-steel reactor hex + hazard stripes vs radioactive green · heavy italic · 124 BPM saw | instability +5.5 %/s and +4/kill, multiplier +0.5 per 20 %, shift = vent for score, 100 % = OVERLOAD (2 dmg through shields) | instability bar |
| 3 | ALCHEMY_CRAFT | emerald + gilt transmutation circle vs magenta/teal · italic serif · 92 BPM sine | IGNIS (solar), AQUA and AETHER (shadow) collect only in their realm; 3 = transmute every enemy | 3 flasks |
| 4 | TIME_ECHO | brass gears + clock dial vs frost · typewriter mono · 108 BPM with dotted-8th echo | each shift spawns a 5 s replay of your path in the realm you left; echoes damage enemies and hold switches | echo pips |
| 5 | SHADOW_LENS | monochrome noir rain · wide-tracked sans · 84 BPM, half-time kick | no realm shifting; shadow runes and enemies are invisible outside the cone; the cone burns them; SPACE = flare | lens angle |

**Pivoting in 10 minutes:** (1) rename strings in `THEME_INFO`; (2) recolour `SKINS` and pick a `TITLE_STYLES` entry in `view/Palette.ts`, add a floor motif in `view/ArenaMotifs.ts`, a tempo in `THEME_BPM` and a music style in `ProceduralMusic.ts`; (3) add a rule branch in `World.updateThemeRules()` / `tryShift()`; (4) add a widget branch in `HudView.update()`. To add a 6th theme, add it to `Theme` and `THEME_ORDER` (TypeScript then lists every `Record<Theme, …>` that needs an entry). Because the engine is pure, a unit test for the new rule takes about two minutes (copy one from `test/engine.test.ts`).

**Fonts:** titles use system font stacks per preset (Georgia, Impact, Palatino, Courier New, Trebuchet MS with DejaVu/URW fallbacks on Linux), so there are no font files to clear with the organisers. If web fonts are allowed, swap them into `TITLE_STYLES`.

### 9.4 Phone co-op bridge

- `vite-plugin-gyro-relay.ts` attaches a `ws` server to Vite's own HTTP server with `noServer` and only upgrades `/ws-gyro`, so HMR is unaffected. It works in `dev` and `preview`. Controllers fan out to all games, and presence counts are broadcast.
- Packets: `{t:'state', a,b,g, jx,jy, tilt}` at 30 Hz, plus `{t:'action', seq}` (deduped by `seq`). Tilt maps to an angle with `atan2(beta, gamma)` and a 6° deadzone. Gyro overrides the mouse only while packets are under 1.5 s old.
- **Gotcha:** phones only fire `deviceorientation` in a **secure context**. Use `npm run dev:https` and accept the self-signed cert once on the phone. On iOS, tap **ENABLE TILT** (that calls `requestPermission`). The joystick and button also work over plain HTTP.
- The HUD shows `PHONE CO-OP → http://<LAN-IP>:5173/controller.html` until a phone links, then `PHONE LINKED · tilt aim N°`.
- **Game → phone:** the game sends `{t:'game', mode, label, sub, realm, accent, accent2, bg, bpm}` (on change, at most every 120 ms) and `{t:'haptic', ms}`. The phone takes on the realm colours, relabels the big button (START / SHIFT REALM / LENS FLARE / SLAM STOP / SKIP / REWIND / PLAY), pulses it at the tempo, and vibrates on hits, PERFECT shifts and coin tiers. The relay caches the last `game` packet so a phone that joins late is in sync at once.
